# UI value types

Which UI types are values (structs and enums) and which are objects, and the rules they follow. This is stage 0 of
[ADR 0002](../../../docs/adr/0002-reactive-ui-model.md). How the compiler stores and passes these values is in
[STRUCTS.md](../../../docs/design/STRUCTS.md).

## Values have equality, objects have identity

A struct or enum compares by value: `==` uses its declared `Equatable` or `Hashable` conformance. A class or interface
compares by identity, and a class cannot declare `Equatable` or `Hashable` (the compiler says to use a struct). An
explicit `equals` method on a class is an ordinary method and does not change `==`. A value converted to `Dynamic` keeps
its own conformance.

## Structs

- **Geometry and color:** `Rect`, `Insets`, `Color`, `LayoutAxis` and `Transform2D` are immutable `Hashable` structs.
  Their fields are final; change one by replacing the whole value.
- **Text styles:** `TextStyle` and `ParagraphStyle` are immutable `Hashable` structs with whole-value replacement
  helpers. A `LayoutNode` keeps both in one lazily created `LayoutTextStyles` holder, only when the node has text styling,
  so an ordinary node holds one pointer rather than two inline optional payloads.
- **Keys and small records:** `DockTextWidthKey`, `Shortcut` and `InkOverflow` are `Hashable`; `EffectParameter` and
  `CustomEffectDefinition` are `Equatable`.
- **Event and text geometry:** `PointerLocation` is an immutable struct in a flat array keyed by pointer id, so pointer
  moves allocate nothing. `TextRangeRect` is an immutable struct in a specialized map, and the text geometry caches are
  made only when something is put in them.
- **App snapshots:** the app's `CncPresentation` and `HobbingTelemetry` are `Diffable` structs owned by their models; no
  caller depends on their identity.

Optional values are `Null<T>`, including inline optional fields: absent and present stay distinct.

## Objects

`LayoutStyle` is a mutable `Diffable` class compared by identity. As a struct it was boxed at every dynamic boundary of
style inspection and allocated far more than the class. Content comparisons use `Diff.mask`; render and style caches keep
`Diff.fingerprint` snapshots, generated by the compiler so their field lists stay aligned with `Diff.mask`. The local-style
cache compares snapshots with `Diff.mask(a, b) == 0`, so equal copies share an entry.

Declarations, computed styles and transitions keep their value kinds: computed styles share immutable typed declarations
until one is modified, and typed equality and interpolation keep structs out of `Dynamic`. Inspection, dumps and
reflection make dynamic values only when asked. A struct is still boxed where it really crosses a dynamic or reflective
boundary, such as inspecting a dynamic style value; a type census shows those boxes as `@haxeon.ui.*`.

Style properties come in two kinds: `StyleProperty<T>` is discrete and has no interpolation function, and
`StyleInterpolatedProperty<T>` owns a non-null typed one. `hasInterpolation` is a field set by the constructors. Giving
every property an optional interpolation function made each enum-typed property generate closure adapters and cast
dispatchers on Wasm.

## Enums

- **Native codes are the generated NativeKit types.** The layout, text, drawing, image, cache, mask, cursor and
  accessibility enums (`LayoutSizing`, `LayoutVisualKind`, `LayoutAlignmentX`, `FontFamily`, `TextAlignment`, `CursorShape`,
  `AccessibilityRole` and the rest) are typedefs of their generated types, so the values are the native codes and the
  boundaries pass them through. A switch over them is checked for exhaustiveness (`E1021`), and an unknown native code
  throws at the switch. Fingerprints and keys use `rawValue()`, never `Type.enumIndex`. Value names follow the generated
  ones, except `CursorShape.Text` for `NK_CURSOR_IBEAM`.
- **`EffectKind` is the one UI enum with no single native counterpart:** it includes operations that normalization removes
  before the compositor sees them, and `NativeEnums.effectKind` maps the rest.
- **UI choices are plain enums** with no integer or string conversions. `ButtonVariant`, `SpinnerKind`, `ProgressMode`,
  `ImageFit`, `SplitSide`, `SplitOrientation`, `TextRole`, `IconName` and `DockPanelHeaderMode` are `Hashable`;
  `EffectKind`, `DecorationKind`, `EffectParameterType` and the host's `UiHostLifecycle` are `Equatable`. Their old
  integers or strings were never a native, wire or file contract. Switches over them name every case.
- **Live patching:** changing how an enum is stored needs a domain reload (`ReloadDomain`); a body edit with the same
  storage stays a patch.

## Calls through interfaces

`ViewportContent.paint(Canvas, Rect)` is the UI package's one use of the constant-time typed interface dispatch: the class
tables live in module metadata, add nothing to instances and allocate nothing per call.

## Native layout boundary

The native layout interface writes resolved geometry into an output buffer that the session reuses, and the session keeps
an immutable result while its fields have not changed. Other values cross the native boundary through the scalar encoder.

## Array growth

Arrays, including struct-lane arrays, keep the target-specific capacity policy. Two uniform policies were tried and
rejected:

### Rejected growth policies

- **Factor 2, and factor 1.5:** both raised HashLink memory.
- **Minimum first capacity:** `max(required, capacity + capacity / 2, minFirst)`, with
  `minFirst = max(4, floor(32 / max(1, elementBytes)))`, on ordinary and struct-lane arrays on all three targets. It
  raised HashLink resident memory by more than was acceptable.

## Measuring allocations on Wasm GC

The compiler flag `--wasm-gc-allocation-count` (CMake option `NKUI_HAXEON_WASM_GC_ALLOCATION_COUNT`, off by default)
counts generated `struct.new` and `array.new` operations; with it off the guest has no counter. From `packages/ui`,
rebuild and measure 120 frames after warmup:

```sh
NKUI_HAXEON_TARGET=wasm-gc NATIVEKIT_WEB_BENCHMARK_BUILD=1 \
NATIVEKIT_WEB_BENCHMARK_WARMUP=120 NATIVEKIT_WEB_BENCHMARK_FRAMES=120 \
./tools/benchmark-web-haxeon.sh
```

It reports `memory.wasm_gc_objects` and `memory.wasm_gc_objects_per_frame`. To build the instrumented Showcase guest
without a benchmark: `NKUI_HAXEON_TARGET=wasm-gc NKUI_HAXEON_WASM_GC_ALLOCATION_COUNT=ON ./tools/build-web.sh`. A paired
comparison must swap the guest the browser loads, `nativekit_ui_haxeon_guest.wasm`, not the build-source
`nativekit_ui_showcase_wasm_gc.wasm`.

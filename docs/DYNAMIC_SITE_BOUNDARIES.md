# Typed dynamic sites: producer and resolution proposal

Status: proposal for dev-71 review, 2026-11-12. This describes existing behavior and a proposed request model; it does not add language APIs or IR variants. Operation names below are descriptive review names, not declarations approved for implementation. The provider model and any new operation or intrinsic require dev-c5's review.

The reachability walk must see an operation at the instruction that can observe a value, including operations emitted by generated code. An any-subject request intersects the set of created types with the provider rows applicable to that operation; it does not invent a type at the call site, retain every method of every class, or imply every operation on a type. A concrete enum crossing into Dynamic retains its nominal subject. Preserve null, exception, identity, aliasing, and exact versus assignable type-test semantics. Native and exported boundaries and externally supplied instances remain conservative until the walk models them explicitly. Do not enable called-only pruning until all the rows below, including late producers, are covered and verified.

## Existing producer and proposed request

| Site | Existing producer and consumer | Proposed typed request and provider row per created type |
| --- | --- | --- |
| Enum to Dynamic, including reflected enum fields and nested containers | `ConversionResolver` calls `EnumDynamicBox.box/view`; `EnumDynamicBox.requestReflectedTypes` is called by `ProgramTyper` for reflected fields and natives. `IrGenerator` emits `EnumDynamicBox(T)` or `EnumDynamicView(T)`; `IrEnumDynamicDispatch` resolves them. | Concrete `BoxDynamic` or `ViewDynamic` for `TypeKey.of(Enum(T))`; do not replace these with an any-subject request. For a reflected field, the reflection producer must carry the concrete field type and request the box only if that field is observable. A view preserves the original array alias and writes. |
| Dynamic to enum, checked cast and type test | `IrGenerator` emits `SafeCast` and `__std_is_of_type`/`__std_is_exact_type`; `IrEnumDynamicDispatch`, `IrCheckedDynamicCasts` and `IrValueInterfaceBoxes` rewrite or generate checks. `IrEnumTagStorage` and inline-enum helpers handle storage. | A known destination requests `DynamicUnbox`/`DynamicTest` for the nominal enum, and the relevant `EnumTagUnbox` or `InlineEnumHelper(unbox)` for physical storage. An unknown type operand requests any-subject type-test, matched against each created type's descriptor/test provider; retain exact and assignable operations separately. |
| Reflect field read/write and enumeration | `stdlib/Reflect.hx` routes `field`, `setField`, `hasField`, `deleteField` and `fields` through `__reflect_*`; `ObjectReflection.generate` synthesizes object-layout dispatch and can box or unbox enum fields without a source conversion. | At each reachable runtime reflection operation, emit any-subject field read, write, presence, delete or enumerate with the field name where available (a dynamic name means all eligible fields). Match per-created-type field/descriptor rows; a read of an enum field requests its concrete box, a write its unbox. Preserve inherited fields and methods, anonymous objects, null and `DynamicObject` behavior. |
| Reflective method lookup and calls | `Reflect.field` may return a method closure; `CallClosure`, `WasmDynamicCalls`, and closure/varargs adapters can invoke it with erased arguments and result. `Reflect.callMethod` itself has no implementation in this checkout. | The lookup requests the eligible named method/closure provider for each created receiver type; a dynamic field name includes every reflectable method. The adapter producing each erased conversion requests the concrete argument/result box or unbox. A future `callMethod` producer must emit the corresponding request rather than relying on an implicit root. |
| Dynamic equality and reflective equality | `CallResolver` emits `__dynamic_equal` for Dynamic `Equality.equals`; `IrGenerator` also emits it for comparisons and reactive paths. `IrEnumDynamicDispatch` and `IrValueDynamicDispatch` select concrete equality; `EnumDynamicBox` currently asks for reflective enum equality. | Any-subject dynamic equality requests `Equals` or `ReflectEquals` as appropriate for every created eligible type, including nested payload dependencies. Keep nonconforming values' current failure behavior; distinguish ordinary and reflective equality, and preserve fallback runtime primitive semantics. |
| `Reflect.compare`, Dynamic ordering and hash | `Reflect.compare` reaches `__reflect_compare`; `CallResolver` has typed fast paths. `stdlib/haxeon/DynamicOps.hx` uses the dynamic comparison result; `stdlib/haxeon/reactive/ReactiveHash.hx` uses `__reactive_hash` for `ReactiveSource` identity (or generates a per-source hint on Wasm). `HashGenerator` requests statically typed `Hash` providers. | Any-subject compare/hash requests only the per-created-type compare/hash or runtime primitive behavior actually selected; use existing `Hash` where it has the required semantics. Determine whether a dynamic hash path can observe enums before assigning an enum hash provider: do not silently substitute typed `Hash` for identity hashing. |
| `Std.string`, interpolation, Dynamic `toString` | `Parser` emits `Std.string` for interpolation; `stdlib/Std.hx` calls `__std_string` (and Wasm array recursion). `IrReachability.withGeneratedRuntimeRoots` currently roots every object's `__string`; Wasm builders generate dispatch. | Any-subject stringification requests the actual string method or enum formatting provider per created runtime type, plus array-element recursion and nested enum dependencies. Do not root unrelated methods. Primitive formatting remains a runtime operation. |
| `Std.isOfType`, exact test and `Std.downcast` | `CallResolver` requires a named type for the first two and lowers them through `IrGenerator` to `__std_is_of_type` and `__std_is_exact_type`; downcast requires a class or interface and expands to a single-evaluation type test plus cast/null. `GenericOwnerErasure`, `IrTypedInterfaceDispatch`, and generated reflection also emit tests. | Known destination uses its concrete descriptor/test/cast provider; a runtime type operand emits an any-subject request. Keep downcast's null result distinct from a checked cast's throw and preserve interface/inheritance tests. |
| `Type.enumIndex`, other `Type.*` APIs | `CallResolver` accepts `Type.enumIndex` only for a statically typed enum and emits `TEnumIndex`, lowered to `EnumIndex`; it rejects a Dynamic operand. No Haxeon `Type` implementation or producers for `getClass`, `enumParameters`, `enumConstructor` or `createInstance` were found in `stdlib` or typing. | Keep nominal `EnumIndex` with its concrete enum. If a supported Dynamic enum reflection or class-construction API is introduced, its actual producer must issue the specific any-subject descriptor/index/parameters/constructor/creation request and per-created-type provider before called-only pruning assumes it exists. This proposal does not add those APIs. |
| Generic, interface, arrays, closures and native ABI | `ConversionResolver` and `IrGenerator` form erased conversions; `GenericOwnerErasure`, `IrValueInterfaceBoxes`, `IrValueArrayBridge`, `IrScalarClosures`, `WasmScalarClosureEscapes`, and Wasm closure adapters create further bridges. Native arguments/results and reflection-generated field access can introduce conversions without an explicit source cast. | Each producer must request the concrete subject's box, unbox, view, interface dispatch or checked cast at the instruction it emits. A native or host boundary with unknown incoming values conservatively retains the relevant externally constructible types and operations. Do not derive adapter requests from signatures in a second walker. |

## Concrete bridge producer inventory

These are separate instruction producers, not additional reachability roots:

| Producer | Erased boundary and operation to carry |
| --- | --- |
| `ConversionResolver` / `EnumDynamicBox` / `IrGenerator` | Scalar enum-to-Dynamic and alias-preserving array views carry the nominal enum in `EnumDynamicBox` / `EnumDynamicView`. `SafeCast` and type tests into a known enum carry the destination. |
| `IrClosedEnumTagAbi` / `IrEnumTagLowering` | Tag storage crossing a Dynamic or logical ABI boundary requests `EnumTagBox` / `EnumTagUnbox` for its nominal type. |
| `IrInlineEnumEscapes` | Inline payload storage crossing the boxed ABI requests `InlineEnumHelper(box/unbox)` for the nominal enum; box and unbox remain distinct typed instructions. |
| `IrScalarClosures` / `WasmScalarClosureEscapes` | Generated closure, cast and argument/result bridges must emit concrete box/unbox operations at each erased conversion they create. |
| `WasmDynamicCalls` / `WasmLinearClosureAdapters` | Varargs, closure adaptation and casts emit tag operations today but still call inline helpers by generated name. Emit typed inline box/unbox as well; retain the logical enum rather than the storage object as subject. |
| `WasmGcClosureAdapters` | Current module-emission adapters carry conversions in backend code. Convert adapters to IR as separately approved, then issue the same operations before the GC builder verifier. |
| `IrValueArrayBridge` | Dynamic array reads box the element and writes unbox it, including tag and inline enum elements. Emit the concrete element conversion while preserving aliasing and cast failures. |
| `IrOptionalScalarFlow` / `IrOptionalValueFlow` / `IrValueArrayOptionalRewrite` | Nullable/optional wrappers and optional array rewrites move values through boxed carriers. Request the wrapper's `OptionalBox` / `OptionalUnbox` as applicable and any nested enum conversion at its actual producer; preserve absent versus present-null semantics. |
| `ObjectReflection` / `IrValueInterfaceBoxes` / `GenericOwnerErasure` / `IrTypedInterfaceDispatch` / `IrCheckedDynamicCasts` | Generated reflection, interface and erased-generic accessors create tests, conversions and calls; their generated bodies emit the operation, including concrete nested enum box/unbox where a field or argument crosses Dynamic. |

## Target boundaries and late producers

These are proposed resolution points, not claims that current runtime-native calls already implement typed requests. The enum phase-order proposal governs the enum operations and their verifier invariant.

* **HashLink:** `IrProgramAssembler` currently builds enum/value dispatch and `ObjectReflection`, then `FrontendCompilation` can add `IrScalarClosures` and its checked casts. Resolve each newly emitted operation before `HlLower` and its verifier/lowering boundary. Plain builds prune in `BackendAssembly`; live builds retain externally callable functions. Reflection and Dynamic native calls ultimately use the HashLink runtime; provider edges must be visible before pruning, including runtime-generated dependencies.
* **Retained HashLink assembly for Wasm:** `BackendAssembly.assemble` copies the logical program and runs `IrScalarClosures.rewrite` for the retained HL image. Resolve that copy's new operations before its HL lowering, independently of the Wasm copy.
* **Wasm32:** `WasmScalarClosureEscapes` and `WasmLinearClosureAdapters` can create bridge operations; `WasmLinearModuleBuilder` appends generated functions and checked casts before reachability and module construction. Resolve their operations before the builder's final verification/emission boundary. `WasmLinearReflection`/`WasmReflectionTable` and `WasmLinearRuntime` provide reflection, type tests, Dynamic equality and stringification; their selected providers must be visible to the walk before it prunes.
* **Wasm GC:** `WasmGcClosureAdapters` currently emits adapters in the module builder. The approved enum plan converts these to IR functions in the builder, with typed conversions resolved through `WasmGcRepresentation` before its verifier. `WasmGcReflection`, `WasmGcModuleBuilder` and `WasmGcRepresentation` implement reflection, type tests, equality and stringification. Dynamic-site operations generated by these paths must likewise become visible before pruning and resolve before emission; verify the exact ordering when those adapters become IR.

At each boundary the verifier must reject unresolved typed operations. During migration, check mode compares requests resolved at the boundary with a full rescan; delete the comparison with the corresponding rescan, not earlier. An inliner test must show that already-resolved calls remain resolved. The walk must handle requests introduced as a consequence of retaining providers until a fixed point, intersecting each any-subject operation with created types; verify incremental codec and warm-edit behavior as well as all three backends with inlining on/off.

## Review questions

1. Approve the operation distinctions and their existing or new provider rows, especially reflective method lookup and field-name granularity. New provider operations require model-owner review before implementation.
2. Confirm which native, exported and reflection paths can supply instances without a visible allocation; these must remain conservative roots until represented.
3. Audit the runtime semantics of enum comparison, hashing and stringification and the exact handling of Dynamic arrays before replacing their fallback dispatch. The source inventory above does not claim unsupported `Type.*` operations exist.

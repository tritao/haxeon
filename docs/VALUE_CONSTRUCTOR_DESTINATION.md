# Value constructor destinations

Status: approved by dev-71 on 2026-11-13, including the value-returning constructor shape decision.

A value constructor must not allocate merely because its body exceeds an expansion limit. The reported six-branch constructor has 19 blocks and remains a call because `IrValueConstructors` expands at most 16 blocks and 64 instructions. The resulting HashLink temporary costs 1,024 allocations / 24,576 bytes over 1,024 operations, with ordinary inlining both disabled and enabled. The five-branch version is expanded and allocates none. Keep the existing bounds: they decide code size, not the allocation behavior of a value construction.

## Why the unexpanded call allocates today

`IrGenerator` lowers `new T(args)` to `NewObject(T)` followed by `T.new(receiver, args):Void`. `IrValueConstructors` expands that call only within its 16-block / 64-instruction bounds. The constructor is an ordinary source function, and `IrScalarAbiEligibility.permits(Ordinary, ...)` does not exclude it. The difference is its signature and mutation: `IrScalarArguments` chooses scalar **result** slots from `fn.result`, but the constructor returns `Void` and writes its `this` argument. Its mutable-receiver logic instead requires snapshot-safety or a receiver-preserving call; it does not turn that constructor into an existing scalar value result. When the call survives, the `NewObject` is used as a call operand. `HlScalarValueLocals` accepts only field operations on a scalar-local root, so that call prevents scalar-local treatment and `HlLower` emits `HlInstruction.New`. A normal eligible function returning a value takes the existing result-slot path in `IrScalarArguments` (caller-owned `IrHlScalarRef` leaves, written on return), allowing its temporary reconstruction to be scalar-replaced.

Generate each value constructor directly as `T.new(args):T`; its default-initialized `this` is a local, and every normal return yields it. Generate `new T(args)` as a plain value-returning call. Reference constructors retain their existing shape. There is no later normalization pass and no old value-constructor form in IR. Make the existing scalar-result eligibility and lowering preserve scalar leaves without materializing the value. Preserve evaluation order, normal-return commit and exception behavior below. This must work independently of the expansion bound. No new destination role or model variant is approved merely for this transformation. If nested values or another concrete case truly require one, send its representation, verifier rule and codec entry to dev-71 via the lead before implementing it, and cc dev-c5 on the model commit.

## Shape and migration boundary

Value initialization needs a typed logical default operation: the current IR has no instruction for a default-initialized value except `NewObject`. Proposed `ValueInit(output, typeName)` creates a value with default leaves without implying a heap allocation; it has no provider operation. Its verifier requires a declared value class and a matching `Obj(typeName)` output. Reject `NewObject` for a value class, and reject the old void, receiver-taking value-constructor definition and call. Port the instruction codecs and state equality; all targets lower it through their existing value representation. This model addition and its verifier/codec details were sent to the lead for dev-71 and dev-c5 before implementation.

The generator and CFG/SSA path, `IrValueConstructors` expansion and scalar argument/result rewrites must use the new shape in the same change. Port value creation and copies in `ObjectReflection`, inline-enum case/lowering helpers, value-interface boxing, optional-value/field flow, value-array bridge/place/optional helpers, scalar closures and value-phi scalarization. Port the inliner, copy elision, load/store and non-null analyses, constructed-type walk, allocation/opportunity census, interpreter, operands and state equality/codecs. Port HashLink scalar locals and lowering; Wasm scalar ABI/locals, flattened fields, call lowering, runtime ABI and both representation backends; GC root analysis and module construction. Existing `NewObject` uses for reference classes remain object allocations. Warm function/cache identity and runtime patch compatibility must reflect the new constructor signature. Update the verifier and all tests/fixtures that build these IR forms in the same commit; there is no compatibility path between the old and new forms.

## One call convention

Use the **existing scalar-result role** for an eligible value constructor. The logical construction result consists of the value's flattened scalar and reference leaves; the caller receives those leaves using the call-boundary machinery already used by `IrScalarArguments`, `WasmScalarAbi`, and `IrScalarAbiEligibility`. It is not a second struct-passing convention. Any genuinely new role requires the separate review described above.

Lower the constructor body once as a normal callable function with the existing result role, regardless of its block or instruction count. Bounded `IrValueConstructors` expansion may still eliminate the call, but both the expanded and unexpanded paths have the same destination and exception semantics. Keep existing scalar-ABI eligibility and explicit representation boundaries: calls that cannot use this convention must materialize at the actual escaping boundary, not because the constructor is large. Recursive and otherwise unsupported control flow must not accidentally be expanded; the non-expanded constructor must still use the destination role when its scalar layout is supported.

The role is logical, not a promise that every backend has the same machine-level signature:

- **HashLink:** extend the existing scalar-result path in `IrScalarArguments`: pass writable references to caller-owned scalar leaves and write them with the existing `IrHlScalarRef` address/store/load mechanism. There is no HashLink multi-value return, and these references must refer to valid caller-frame slots, not a heap object or a temporary whose lifetime ends during the call. Preserve managed references and GC visibility. A constructor that throws must not publish uncommitted leaves to an observable destination.
- **Wasm32:** use `WasmScalarAbi`'s scalar result components and existing multi-value return lowering. The caller collects the returned leaves into its chosen local destination and performs any later commit; the logical destination role is not a parallel linear-memory struct ABI.
- **Wasm GC:** use the same `WasmScalarAbi` role and multi-value result contract, with reference-typed leaves represented using the existing GC types. Keep reference types and GC visibility exact; do not introduce a boxed payload or change value/enum storage layout to implement the call.

The ABI planner must choose the role and its leaf types/order from the logical value layout, and both caller and callee must agree before backend lowering. Verify the role, leaf arity and types at the call boundary. The existing target-independent scalar eligibility predicate remains the single authority for whether a declared function can use the convention; target planners implement its physical realization. This proposal does not grant a new provider operation or establish a second eligibility list.

## Evaluation, aliasing and exceptions

Evaluate the destination owner and every constructor input in source order before the first destination write. For `p = new Point(p.y, p.x)`, both reads observe the old `p`. Direct construction into a fresh local or a function's private return slot is allowed only when the destination cannot overlap an input and no observer can see partial writes. If non-overlap cannot be proved, snapshot inputs and construct into scalar locals before the final copy.

A field, array element, captured place, or other observable destination is not a private construction slot. Evaluate its owner/index and all inputs in language order, construct into private scalar locals, then commit the completed leaves to the destination only on normal return. A throw must leave the old observable value intact, including when the handler can inspect it; preserve original null and bounds checks and exception order. The final commit must respect the existing nested-value and optional-presence copy rules. No heap temporary is needed merely to stage those leaves.

## Warm builds and live patches

The destination role and ordered leaf layout are part of **function signature identity**, not an optimization inferred only from a call site's current body. Include the declared role and physical leaf types in the signature/fingerprint used by scalar specialization, cached lowering and `HlFunctionCache.signature`, and in the corresponding runtime ABI/patch compatibility decision. A role or layout change invalidates all affected callers and cached lowering. `HAXEON_CHECK_REUSE=1` must compare the rebuilt and fresh result and reject a stale caller. A live patch must never mix the old value/object-return shape with the destination shape: use the existing incompatible-signature reload/retirement path rather than patching one side in place.

The 16-block/64-instruction expansion decision itself must not change the destination role or signature. Add a warm-edit test that changes a constructor from five conditional assignments to six and back, crossing the expansion limit while retaining the same logical signature. Check both reuse modes against a fresh build, the result and zero temporaries. Separately exercise a genuine role/layout change and verify caller invalidation and safe live-patch handling.

## Acceptance tests

Port the bounded-constructor repro and assert zero temporaries for 1,024 six-conditional constructions on HashLink with inlining off and on; compare allocated bytes as well as count. Exercise Wasm32 and Wasm GC in both inline modes and require equivalent values and exceptions. Cover input/destination aliasing, observable fields and array elements, throwing constructors observed by a handler, nested values, managed references and nullable leaves. Include a body over the expansion bound and an equivalent body below it, plus the warm-edit and incompatible-signature cases above. Test an actual escape separately so the unavoidable boundary allocation is attributed to the escape, not to the constructor's size.
